# Cell

`CellSqlDriver` adapts one Durable Object's SQLite storage to the portable store.
It uses `transactionSync` for transactions and reads `changes()` for direct row
counts. Mac connection pragmas are ignored because the platform owns them. Closing
the facade leaves platform storage intact. All connection state stays on the driver
instance.

The driver tests use an in-memory SQLite implementation of the platform surface.
They verify migrations, receipts, rollback, trigger row counts and instance isolation.
The workerd tests cover routing, hibernation and restart on the actual platform surface.

## Worker foundation

The entry Worker verifies ES256 signatures with a ten-minute public JWKS cache,
checks the org in the URL and removes caller-supplied internal headers. It routes
requests to one SQLite Durable Object per org. Only a separate, two-minute HS256
service token with audience `cell-service` can delete an object. The orchestrator
uses the same separate service key with audience `orchestrator`; client signing
keys never sign service requests.

Before opening storage, the cell checks active membership, session, device and
runner grant state through the configured account service's `access` endpoint.
Positive results last at most thirty seconds, including across repeated requests;
an unavailable service fails closed after that window. Client and Mac runner
claims must reference an account session. Sandbox claims reference their task.
The first active member owns the object in milestone 1. Schema initialization is
lazy so a deleted account cannot recreate its store after eviction: the global
account service must deny that account before storage opens. No raw bearer token
is persisted.

`wrangler.jsonc` contains placeholders. The hosted deployment supplies its own
config and service key through the environment. Nothing here deploys a Worker or
creates a Cloudflare account resource.

Cloud project creation/listing, task creation/update/cancel/retry/review, thread
metadata/history, interaction answers and usage requests now use scoped core
handlers. Snapshot responses contain metadata; transcript history is paged by
thread. Unsupported methods return `method_unavailable`. W4 is still incomplete:
diff/publication results are pending. Runner
delivery, connected Mac scheduling and sandbox lifecycle alarms are implemented below.

## Test runtime

`pnpm test:cell` runs Node driver/auth tests and real local workerd tests, without
windows or accounts. The runtime suite generates its own service key in memory.
The root test command also runs both suites. The cell has its own runtime typings
and typecheck so Worker globals do not alter the Mac's Node/DOM typings.

Cloudflare renamed the maintained Vitest integration to
`@cloudflare/vitest-plugin`. The `@cloudflare/vitest-pool-workers` dependency is an
npm alias to that package, preserving the spec's dependency name while using the
current local runtime. It requires Vitest 4.1; the cell keeps that version isolated
from the rest of the workspace. Worker binding types are generated by `pnpm
--filter @zoltbot/cell types` and checked in. Do not edit them by hand.

Scoped metadata reads pass requested entity kinds to `Store.read`. They perform
separate indexed ID queries because workerd rejects the desktop query's compound
SELECT. Message bodies are hydrated only for requested IDs. The runtime eviction
test exercises the real migrations and durable receipts, complementing the Node
shim tests. Boundary checks refuse daemon/native dependencies and full store
snapshots in cell source.

## RPC, sockets and alarms

A command's durable identity hashes the org, member, device and client command ID.
Receipts also store a hash of the method and canonical parameters, so reusing an
ID for changed input fails. Raw parameters are never copied into receipt metadata.
Receipts retain the trusted member/device/surface actor. Core handlers replace
caller-supplied answer attribution with the authenticated member. Tests check that private answer values appear in neither events nor
receipts.

Clients use hibernating WebSockets tagged `client`. Their attachment holds verified
claims, subscription state and the last event sequence sent, never a bearer token.
Reconnect supplies `lastSeq`. Replay reads one event at a time and sends bounded
batches. An alarm continues replay and checks account revocation with a fresh
request every fifteen seconds, independently of the HTTP access cache. Expired
claims close the socket. A reconnect authenticates again.

Alarms resume a persisted projection rebuild cursor after eviction. Each store
step reads one event at a time and stops at the event count or after one MiB of
encoded events; one larger event can exceed that threshold. The Mac's one-shot
rebuild stays unchanged. Tests cover an interrupted rebuild and metadata reads
from a database containing over one GB of synthetic message events.

`CellLeases` stores one fenced runner per task, its event acknowledgement and its
heartbeat in SQLite. Event acknowledgements participate in the receipt transaction.
A missing heartbeat marks presence offline after sixty seconds; it does not permit
another runner to take the task. One wake operation is persisted before network
I/O. Failed requests retry the same operation ID. A matching heartbeat clears the
wake marker; a successful old wake response cannot overwrite a newer heartbeat.
The real runtime tests exercise rollback, duplicate receipts, eviction, heartbeat
recovery and refusal of a second writer. Runner delivery is covered by the socket tests described below.

## Runner delivery

Runner sockets authenticate before `runner.hello`; the hello binds their device
ID and the two supported CLIs. A Mac accepts no new tasks until `acceptTasks` is
true. Drain stops new assignments while retaining existing leases. A sandbox
receives only the task in its token. A replacement connection closes the old
socket for that device; it does not transfer the lease to a different runner.

The cell sends the saved acknowledgement cursor before each lease. It starts a
queued task through the shared core handler in the same transaction that assigns
its lease. Each task revision saves its selected project/profile/definition and
brief, so reconnect does not silently change launch configuration. The launch
manifest uses a relative `cwd` (`.`); the runner resolves it inside its managed
checkout. Only queued input items and the latest native continuation ID accompany
the frozen configuration. Neither full transcripts nor credentials enter leases.

Runner observations include session, item and turn identities from the normalized
runtime. The cell fences the task/runner/lease, requires contiguous sequence
numbers and dispatches `runner:<taskId>:<runnerSeq>`. Its receipt and runner cursor
commit together. Duplicate delivery returns the saved acknowledgement. Projection
uses the shared runtime, input, interaction, usage and task-result handlers.
A new session for a previously opened native conversation must confirm the same
native ID. A runner cannot replace an item of another kind, including human input.
A duplicate old turn completion cannot finish a newer task revision.

The runner transport permits two MiB per message, covering the adapters' one-MiB
native frame limit plus normalized context. Client requests retain their 64-KiB
bound. Hibernation attachments retain connection IDs so a stale handler cannot
overwrite the identity or replay cursor set by another handler. Close codes reserved
for local diagnostics are normalized before sending a close frame.

The workerd tests drive the actual runner WebSocket through hello, lease, event,
acknowledgement and a mid-turn eviction. They also cover Mac opt-in, tasks created
after connection, drain and refusal to write another runner's task. Sandbox
orchestration and runner command delivery remain W4 work.

## Sandbox lifecycle effects

`CellSandboxes` saves a create, wake, sleep or destroy operation before calling the
orchestrator. Each retry sends the same `Idempotency-Key`, including after object
eviction or an uncertain response. The response must match the org, member and
task. Provider credentials never enter these records. Only fixed error codes
reach task holds and operation records. The orchestrator owns usage accounting in
the same idempotent operation; the cell must not record a second charge on retry.

Maintenance scans at most eight tasks per call. A durable cursor carries the
earliest future alarm across pages. Idle tasks sleep after twenty minutes;
questions can keep a process-preserving target awake for thirty minutes. Before
the provider lifetime ends, an active model turn must finish its checkpoint before
sleep. A checkpointed task resumes through the existing core continuation note,
retaining native session metadata and advancing the item sequence. Retained
terminal sandboxes are destroyed after twenty-four hours. An injected liveness
check prevents in-flight responses from writing after org deletion. The cell also
checks deletion before scheduling alarms or broadcasting to more sockets.

The lifecycle controller now runs from `OrgCell` alarms. HTTP requests schedule
an alarm even when there are no open sockets. An active turn first commits its
checkpoint and an interrupt command together; the controller waits for the
normalized turn completion before pausing. An intentionally sleeping sandbox does
not count as an offline runner that needs an immediate wake. Failed offline wake
requests keep their original operation ID and retry without disconnecting clients.
Deletion explicitly removes the alarm as well as SQL/KV storage.

`CellCommands` saves commands with their task's lease and runner. Hello replays
unacknowledged commands; connected runners retry after fifteen seconds. Results
are fenced and accept only the command's bounded result schema. Basic command
acknowledgements are exactly `{ok: true}`; arbitrary error details never reach
storage. Diff and publication results remain unsupported until their own bounded
schemas and review checks land. Private answer values are refused by the generic durable
queue; the answer-delivery path below handles them.

A connected runner also receives a refreshed lease when new queued input arrives,
including a continuation created after wake. A durable input marker prevents
repeated broadcasts of the same queue. Reconnect still resends the lease and its
acknowledgement cursor. Runners must merge canonical queued item IDs idempotently.
The workerd socket test checks continuation in the existing native conversation,
command delivery and acknowledgement, and no repeated lease for unchanged input.

Lifecycle response storage and core events share one `Store.dispatch`. The store
forbids nested dispatches. Service requests clear their deadline timer after the
response body is read, so a completed request does not keep the object alive until
the deadline. The restart tests cover that cleanup. W4 remains incomplete.

## Task input and stop requests

`turn.send` queues a canonical input through the shared core handler in the task's
existing thread. It requires a started task owned by the authenticated member.
The transaction reads the latest item sequence without hydrating the transcript.
Receipt replay returns the same input ID, and the next lease offer delivers that
ID to the assigned runner. Project-only threads have no runner in milestone 1.

`turn.interrupt` uses the shared human-interrupt handler and commits its note,
audit and runner command together. The command names the selected turn; a runner
must refuse it if a different turn is now active. Lifecycle checkpoint interrupts
also name their active turn. Task cancellation atomically queues a stop for its
existing lease, while an unassigned task needs no native stop.

## Native answer delivery

Client answers use the existing core validation, redaction and trusted human actor.
The cell removes caller-supplied automatic attribution and refuses view attribution
without a view context. A normal answer saves its runner command in the same
transaction as its resolution. A sleeping sandbox wakes for pending answer delivery;
no new chat message is required. Reconnect retries the same command and interaction
version. The runner resolves its local binding by interaction ID or native reference
and must enforce that version before responding.

A private answer requires a live, recently heartbeating socket for the task's
assigned runner. Its raw value goes directly to that socket once, after the core
resolution commits. Durable delivery rows hold only the redacted resolution and
lease metadata. They never replay private values after eviction. A missing
acknowledgement after thirty seconds adds the existing unconfirmed-delivery note;
a late valid acknowledgement reconciles that note. An unavailable runner refuses
a private answer before committing it. The caller can retry when the runner is back.

This follows the Local interaction engine's saved-answer/uncertain-delivery
semantics. Native failures contribute fixed metadata, never raw error details.
Batch answers commit together; a missing private handoff rolls the whole batch
back. Ordinary runner commands cannot authorize the signed Mac bridge in W7.

Deletion closes the old SQL facade before deleting storage. Code that retained
that facade cannot create queue tables after its async work resumes. A runtime
test captures the old facade, deletes the org and verifies queue creation fails
with no tables or alarm remaining. It does not claim to reproduce every HTTP
timing. Copy review covered the existing saved-resolution component and the note
text; cloud client rendering remains part of W10/W11 verification.
