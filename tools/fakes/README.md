# Fake provider tools

The four fake CLI programs speak the provisional wire shapes from file 03. YAML scripts specify outbound frames, expected inbound messages, replies using the last request id, delays, malformed records, crashes, and hangs. Normal scenarios live in scenarios. They are synthetic and do not prove the behavior of an installed provider version.

Run a fake from the repository root:

```sh
TSX_DISABLE_CACHE=1 node --import tsx tools/fakes/src/fake-codex.ts tools/fakes/scenarios/codex-normal.yaml
```

Codex checks handshake order and validates incoming request envelopes. Set FAKE_CODEX_SCHEMA to a JSON Schema generated by the installed CLI to validate that version's full request catalog. The bundled conservative envelope is labelled provisional. Real adapter tests must use the schema and recordings from their spike.

The test reference provider is a separate wire server that emits normalized events. Its adapter runs every shared conformance scenario. It is never offered as a production provider. Two intentionally broken variants demonstrate that losing final messages or blocking requests fails conformance.

Test frame artifacts stay in .cache/test-results/conformance. Failed conformance assertions include a redacted normalized trace and frame tail. The recorder writes version metadata and normalized private paths, and masks credential fields and registered values before capture output is persisted.

The ACP conformance provider is a stateful protocol version 1 wire server. It emits ACP session updates and permission requests, verifies session loading against a local native record, and calls the injected host HTTP endpoint. Its adapter uses the production supervisor transport. All 22 shared scenarios run without skipped tests. Providers that expose context usage without token counts are tested against that capability, and unsupported native question cases remain covered by dedicated form tests.
